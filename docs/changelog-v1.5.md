**The registry: why it was built mid-session.** While scoping the Space Opera pack's "stays off celestial bodies" boundary, Drak flagged that Ephemeris Astronomical Bodies don't appear in Concordance. Verified against r074 code: `GraphView` builds nodes only from `state.entries`, its `addLink` guard hard-drops any edge whose endpoint isn't in the entry `idSet`, and the wiki-link `nameToId` is entries-only — so bodies (in `state.celestialBodies`) are invisible as nodes AND any surviving legacy entry→body ref is dropped. The author side has the twin gap: the entry-ref picker lists only real templates. View triage (verified): **Concordance** (read) and the **entry-ref picker** (author) are the real gaps — type-general surfaces. **Linea** (relationKind-only) and **Chronometric/Timeline** (calendar-dated) are correct-by-design, not gaps. **Stemma** and **Cartographia** are soft manual-surface gaps. Root cause: "entry" is the only first-class linkable node type. This is the exact wall ConLang would hit as its own state slice — so the fix is **general**, landing pre-ConLang.

**Design (locked through proposal-review before code):** a **registry of first-class linkable node types**. Registering a type buys two things — graphable in Concordance (its nodes + intra-type edges) AND ref-targetable by entry-ref fields. **Registration is a DATA CONTRACT, not an API**: each source supplies a descriptor `{id, name, color, icon, refEligible, getInstances(state), getColor(inst), getEdges(state)}`. A registered type presents as a **synthetic template** so the existing templateId-keyed machinery (picker, coloring, name→id) reuses with minimal branching. Core views satisfy the descriptor in code; a future pack could satisfy the same descriptor by declaration once Packs grows past templates-only — the descriptor is kept declarative so that door stays open at no cost now. Packs as they exist need do NOTHING (their instances are entries, already first-class); a pack CAN *target* a registered type by name in `refTemplates`, resolved via the same `fix()` name→id path — which makes the **registered-type names a published allow-list** that becomes part of the pack-authoring contract. Body-as-first-registrant behavior, all locked: all bodies as nodes (incl. narrative kinds), one node per record, no dedup; Ephemeris kind-palette coloring; orbital hierarchy (`parentBodyId`) drawn as "orbits" edges (the sector graph, free); entries can target "Astronomical Body"; bodies usable as Stemma nodes + Cartographia pins; on Ephemeris delete the node disappears + inbound ENTRY refs silently scrub (no dead label) with a "referenced by N entries" count shown BEFORE confirm; type name "Astronomical Body".

**r075 — Foundation.** `NODE_SOURCE_REGISTRY` + the Astronomical Body registrant (instances from `state.celestialBodies`, color via `observeColorForKind`, edges = `parentBodyId → body` "orbits"), `getRegisteredSyntheticTemplates`, and the read helpers (`getRegisteredGraphNodes/Edges/NameToId`, `isRegisteredNodeId`, `resolveRegisteredNode`). Seam only, nothing consumes it yet — mirrors the r062 grid foundation.

#### Orbital math depth: full Keplerian (scoping update)

Follow-up scoping decision. Initial Ephemeris scoping was framed as "simplified Keplerian" (mean longitude as position, coplanar-circular assumption). Reviewed the cost delta to full Keplerian and confirmed the upgrade is worth it: ~50-80 lines of additional math (Newton-Raphson solve of Kepler's equation, true anomaly conversion, three-rotation chain to inertial frame), ~10-20× more floating-point ops per body evaluation, still negligible at worldbuilder scales. The schema does not change — the six classical orbital elements were already in scope. The decision affects three workspaces: Compute uses real 3D positions for alignment math, Observe renders bodies at their actual orbital positions, AsBo's eccentricity input clamps to 0-0.99 on save (elliptical orbits only; parabolic and hyperbolic out of scope).

Three drivers for full over simplified: eclipse alignment requires real 3D positions to avoid phantom eclipses on inclined moons and missed eclipses at non-zero ascending nodes; eccentric orbits deviate significantly from mean longitude near periapsis (matters for comets and elongated moons); cost delta is bounded and well-understood. Phase alignment math is unaffected — it uses cycle-position modular arithmetic and works identically under either model.

Code cost estimate bumped from ~980 lines to ~1050 lines in the roadmap. Doctrine entry added.
