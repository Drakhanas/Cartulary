=== 2026-10-19 (session 18, v1.6 pillar 2: r026 header split + rotation, r027-r030 the four view carves) ===

Five r-bumps and the map-independent phase is done. The session also lost its working
directory halfway through and the only reason that cost minutes was a rule written for a
different failure.

It opened the way the last two did, with the handoff read against the tree before anything
got cut. The source bundle wasn't in the uploads, only the staged HTML and the docs, so I
rebuilt the module tree from the babel body and the published per-arc counts, which was a
hypothesis with 34 file boundaries in it. Everything testable held: counts, census, hash,
anchor bytes, every relocation destination, every span tiling its arc. When Drak sent the
bundle the reconstruction matched it file for file, so the audit stood. Three prose defects
again, and the worst was the small one: "82 characters, not the 81 section 11 states", when
section 11 already said 82. The correction had been made everywhere and the sentence
describing the discrepancy had survived it. I went looking for a contradiction, found
agreement, and briefly distrusted both documents, which is the cost of narrating a fix instead
of making it.

Drak didn't want the defects fixed before the cut, which was right. r026 went in as specced:
two strings at 82, one header rewritten in place, one inserted with its blank. Every number
in the r025 table landed exactly, including the three named pair changes, and that was the
first time this project gated a cut on a written delta instead of a verdict. It worked. It
also only worked because the delta was three lines, and the thing the spec had not said was
that the anchor would need to rotate afterwards. Obvious at the cut, absent from the plan, so
it went into the doctrine as the kind of gap a fresh chat executes into.

Then the sandbox reset between two turns and took cartulary-src, inlining, and the scratch
reconstruction with it. The outputs directory still had the browser-passed r026 file. So the
replay was: unzip the r025 bundle, run the r026 script, rotate, rebuild working, and compare
the hash to the artifact Drak had passed. Same bytes. The rotation procedure's last step was
written to catch a freeze of the wrong body, and it turns out to be the exact check you want
after an environment loss, because the hash is the one thing the sandbox can't have faked. If
any step in r026 had been a hand edit there would have been nothing to replay.

The carves themselves were the quietest part of the session, and the order was the only
decision in them. Three of the four shared 16_trunk with their spans published as line
numbers inside that arc, so cutting front to back would have invalidated the later spans at
every step, and re-deriving spans is precisely the operation that produced two wrong editions
last session. Back to front leaves the remaining spans alone. I put that to Drak as a fork,
he took it, and three carves went through without a single re-measurement. Every seam printed,
every seam matching, every cut script asserting its members by name and rule 1 at both ends
before touching the tree. Kalendarium was a rename.

Two things bit, both in the harness, neither in the product. The r027 script aborted before
writing because its existence check tested rename destinations against the tree as it stood,
and the trunk arc numbered 23 was both a destination and a source; the reverse-order rename
handled it at mutation time and the pre-check didn't model that. Then prove_gate_teeth crashed
on the reflowed tree because its misfile probe hard-coded the kalendarium and home-data paths
by their old prefixes, 19 and 20, which had become 23 and 24. One session after the doctrine
entry about filenames decaying in documents, the same decay turned up in a probe. And at
turnover the doc gate's own probe harness had the same disease worse: prove_teeth hard-codes
the r025 tree figure, so its published-figure probe stopped proving anything the moment the
tree changed, and it stopped quietly rather than crashing. A probe whose target is a literal
from one session proves that session.

Pattern for the session is the same as the last two, and I'm starting to think it's the shape
of this project rather than a run of luck: the artifact held every time, the documents and
the harnesses are where the defects live, and the defects are all the same kind. Something
that was true when written and nobody re-derived. The fix every time has been to make the
thing executable or to make it derive its target from the facts the gate already checks.

Next is pillar 3, which is the one pillar a user can see, and the first thing it needs is not
code. r026 showed what a content edit looks like under the current gates, which is a table and
a browser pass, and a feature cannot be gated that way. Whether a third mode earns its keep is
Drak's call before the first editor line lands.

=== 2026-10-19 (session 19, v1.6: handoff audit, the scoped-edit gate mode, source and docs into GitHub, r031-r051) ===

One cut tonight, late, and before it the session had already changed more than most
sessions with five.

It opened with the wrong file. The upload named cartulary-modular-src_r030.zip was the
turnover doc set, and the real bundle was nowhere on Drak's disk because it had only ever
existed as a file card in Chat 63. So the first hour was the audit I could do without a tree:
the babel body inside the browser-passed r026 artifact is the anchor by the handoff's own
account, and every published figure reproduced from it, down to the 203-byte delta over the
r025 anchor decomposing into one 184-byte header-plus-blank and a 19-byte rewrite. That was
satisfying in the way checking arithmetic is satisfying. It also meant that when the bundle
finally arrived, two hours later, there was nothing left for it to surprise me with, and
there wasn't.

In between I built the thing pillar 3 needs. Drak picked the scoped-edit mode from a
three-option list in one character, which is how he picks. The design question was what a
content edit can promise when it is adding lines on purpose, and the answer that held up is
the complement: everything it did not declare. Declare the files and the declarations, and
the gate holds the rest to the anchor byte for byte. I tested it the only honest way
available, by replaying r026 on the real r025 bundle, and it printed the delta table the
r025 handoff had written by hand, line for line, then froze the same sha the artifact
carries. The harness got eleven new probes, one of them a positive control, which the old
seven never had; a gate that only ever fails is a gate nobody has tested either.

I built it against a reconstruction, because the bundle was missing, and I was uneasy about
that the whole time. The handoff says not to reconstruct, and it says it for a reason. When
the real tree landed it matched the reconstruction byte for byte, trailing newlines and all,
which is a nice thing to learn about the published figures and changes nothing about the
rule. Nothing from the reconstruction shipped; everything was re-run on the real tree.

Then Drak said the thing I had been circling: the turnover handling had become the hazard.
He was right, and the May conversation that decided against git had been right too, for a
616 KB file in a container that could not push. Neither fact survived. An hour later the
tree, the tooling, the tarballs, every document and archive, the site, and the packs were in
a private repository with CI running all six gates on the push, green first time. The two
things that could have gone wrong quietly were line endings and hard-coded paths, so the
first commit unset text conversion for every file and made the three scripts find their own
root. The session's credential refuses to push tags, which is a small indignity I'll leave
to Drak's clone.

The pattern I named last session, that the artifact holds and the documents and harnesses
are where the defects live, got fixed at the root tonight rather than getting another
doctrine entry about it. Copies were the mechanism. There is one copy now, and a machine
checks it on every push. The doctrine entries I did write are about why that is true, not
about being more careful.

Then pillar 3. The build order went to Drak as eight cuts with their declared scope, SVG
and layers and a parchment background already decided by him in one line, and he locked it
in one line. Cut 1 was the data model, which is the dullest possible first cut and the
right one: thirteen declarations, a migration that touches every map record, and nothing on
the screen to show for it. That last part is the problem with a data-model cut. The checklist
says "existing maps unchanged" and a person cannot see an absence. So I built a world in the
old shape and loaded it into both builds in a headless browser, with the libraries served
from the tarballs we had kept for the finals, and diffed the two: pins, labels, scrubber,
screenshots, exports. Identical except the two new keys. Drak asked, reasonably, how he was
supposed to open an existing map when there has never been a way to import one; the answer
is that there never will be, a map is a record in the world file, and the fixture was the
answer to his question before he asked it. He passed it. The anchor rotated for the ninth
time, the first time through the gate I built this session instead of a table, and the
rotation's last check, the rebuild hashing to the file he passed, held.

The probe found one thing the build sheet got wrong, which is the right number for a first
cut: the migration cannot know an image's size, so the rule that says it does belongs in the
renderer. Recorded for cut 2, not patched into cut 1.

Cut 2 went the next morning, after the tag landed on the wrong commit and had to move. The
renderer is one tree and two serializers, which is the kind of sentence that sounds like a
slogan until you write the export path and realize the alternative is two drawings of the
same map that agree by luck. The probe this time had fifty assertions and the one I cared
about was dull: every pin's anchor point, measured against the svg's rectangle, within a
percent of the stored fraction, in the app and in the export. The map moved from an img to
an svg and nothing a user placed moved with it. Drak's note on the pass was that there was
nothing to test but pins, new maps, and the zoom, and that is exactly right; a renderer with
no tools is a change you prove by showing nothing changed, and the parchment map with every
shape type exists only because a fixture can carry shapes the editor cannot yet make. Cut
3 is where the map stops being a thing you look at.

And it was. Six forks proposed, six recommendations taken in four words, and then the first
cut in this project that Drak sent back, three times, each time right. A polygon that looks
like a line because the default fill was the color of the paper. No way to stop drawing
without throwing the shape away. A line you could not grab because its hit area was its own
stroke, under two pixels wide. And then the handles I added for him, dead at their centres,
which I would have sworn worked because the probe said so; the probe had dragged a corner
that sat on the shape's own hit area, and a whole-shape move gave the same number as a
point move. That one goes in the doctrine. Every round was the same shape: revise the
script, put the two files back to r032, replay, gate, probe, stage. Nothing was ever edited
by hand, and the script that is committed is the one that produced the tree, which is the
whole point of the procedure and the first time it was tested by someone changing their
mind mid-cut. Eleven rotations. The map takes a coastline now.

Cut 4 went in one round, which after cut 3 felt suspicious. Text, undo, layers: five forks,
five recommendations, four words back. The one I argued against the sheet on was undo. The
sheet said drawing only, and the sheet was wrong in the way plans are wrong, by guessing
that narrower is cheaper. A snapshot of the record is a snapshot of the record; the pins
ride along for nothing, and the only design in the whole feature is naming the gesture so a
drag is one step. The probe caught the one bug before Drak could, and it was a focus bug,
which is the kind that only exists once there is a text field: a label coming back from
undo re-mounted the field, the field grabbed focus because it had been told to on mount,
and the next Ctrl+Y went to the field instead of the history. Drak's pass found a bug that
was a hidden layer, which is the feature working and the interface not saying so loudly
enough; noted, not built. Twelve rotations. Four cuts in one session, three of them today.

Cut 5, r035, was two jobs wearing one number. The feature went in clean: four stamps I drew
as path data, a frame that turns with its shape, corners and a knob, and the arc Drak asked
for when I showed him the forks, which turned out to be the most interesting problem of the
cut because the export has no DOM and the editor does, and a label that sits in one place
in the app and another on the page is worse than a label that is slightly off in both. So
nobody measures; everyone estimates, the same way. The second job was the room. His pass
never touched a stamp. It found the resize grip stopping at 100%, which it had always done;

Thirteen rotations. Five cuts in one session.

Cut 6, r036, stamp packs, the first time Cartulary takes markup from a stranger and draws
it. I offered six forks and Drak took five and turned the sixth, and the one he turned was
the right one to turn: I had proposed the collision modal the sheet asked for, Skip,
Replace, Rename, and he said nobody has seen these ids yet, namespace them by pack, because
a Replace that puts a pack's tree where the built-in tree stands is a Replace that, once the
pack is deleted, leaves no tree anywhere on any map. A modal is a user interface for a
collision; a namespace is the absence of one. The sanitizer taught me the other lesson of
the cut. My first one parsed as XML and refused the first realistic test body because it
carried an xlink prefix with no declaration, which is what every Inkscape file carries and
what every browser draws anyway. The app renders a stamp through innerHTML; the exported
page renders it through the HTML parser; a sanitizer that sees a different tree from the
renderer is wrong in both directions. So it parses as inline svg in a page, the way it will
be drawn, and then rebuilds from the allowlist. His pass found the panel in the wrong place
(bottom; there will be fewer stamps than maps) and a Project view that called a world with
maps and no entries empty and hid the export button, which had been true since r001 and
nobody had a map-only world until now. Fourteen rotations. Six cuts in one session.
