### Session 2026-06-30 (session 12, v1.6 pillar 2 phase-1 continued: build pipeline reworked to assemble from a module tree, canonicalizer + reconstitution gate built, first three carves home-data/modals/io-utils, all browser-verified)

**r-counter policy changed (Drak's call).** From here, one r-bump per FULL carve, not per HTML edit. A carve is pure relocation into files, so its assembled output is byte-identical to the prior build; the old "increments only on HTML changes" rule would never move the counter through the whole modularization. r004 = the pipeline rework + the home-data carve (one full carve); r005 = modals; r006 = io-utils. r002/r003 keep their numbers (they predate the policy, staged as monolith HTMLs under the old rule).

**Source is now a tree, not one HTML.** The working HTML split into `cartulary-src/shell.html` (the page scaffolding, one `@@CARTULARY_BABEL_BODY@@` sentinel where the babel body injects) plus `cartulary-src/modules/NN_name.jsx` (the babel body carved into modules; `NN` is a two-digit assembly-order prefix `sorted()` honors, `name` is the module/carve name). Concatenated in `NN` order, the modules reconstitute the body. A frozen `cartulary-src/reference-r003-body.jsx` is the parity anchor every pure carve must reassemble to.

**build_inline.py reworked** (Python infra, folded into the r004 cut). Three modes: `working` assembles shell + tree into the working HTML (CDN head, raw babel block) for parse/stage/browser; `verify` runs the reconstitution gate; `finals` is the unchanged dual-build (precompile + inline + license + CDN swap), release-prep only, now fed the assembled HTML. Assembly is ordered concatenation, never dependency resolution: resolution reorders declarations and breaks both byte-parity and eval-order.

**canonicalize.py (NEW)** defines the normal form the gate compares against, once, so the diff is a clean signal every carve. Two comparison strengths: `canonical_sequence` (ordered non-blank, trailing-trimmed lines, position-sensitive) is the gate for a pure split, where order is preserved by construction and any reorder/add/drop shows; `canonical_multiset` (order-independent count of the same lines) is the gate for a relocation/gather (the r002/r003 operation), where lines move on purpose. `decl_names` is the independent 419-name invariant. Blank-line and trailing-whitespace differences are ignored, so join noise or an editor-added newline can't false-fail the gate.

**Gate proven to have teeth.** A green run only shows the pipeline reconstitutes; it does not show the gate can catch a bad carve. Negative-tested: dropping one code line from a module drives the gate RED (37,301 vs 37,302 lines, first divergence pinpointed); renaming a top-level declaration drives it RED with the decl-set diff. Both restore to green. A gate that only ever passes is worthless; the negative test is what makes the green trustworthy.
