## The tree

The working HTML is not the source. The source is:

- `cartulary-src/shell.html`: the page scaffolding, with one `@@CARTULARY_BABEL_BODY@@` sentinel where the babel body goes. The body's trailing newline belongs to the shell.
- `cartulary-src/modules/NN_name.jsx`: a flat module. `NN` is the two-digit assembly order; `name` is the module.
- `cartulary-src/modules/NN_name/NN_part.jsx`: a directory module. The directory carries the outer prefix and each part its own `00`-based one. Three exist: `18_cartographia/`, `23_glossopoeia/`, and `24_ephemeris/`.
- `cartulary-src/reference-r020-body.jsx`: the frozen parity anchor, active as of v1.7's r020. Found by glob, never named in code: exactly one `reference-r###-body.jsx` may exist, and the gate refuses on zero or two. Its companion `reference-r020-layout.json` holds the per-file line counts that segment it, its sha256, and the shell's text and sha256; `edit` needs it and `freeze` writes it.

**Assembly is ordered concatenation**, never dependency resolution: the modules are joined in path order with a per-file `rstrip('\n')` and injected at the sentinel. Resolution would reorder declarations and break both byte parity and evaluation order. Because of the `rstrip`, **no file may end on a blank line** (boundary rule 1 below); every file leads with a blank, none ends on a blank, and none ends on a comment.

## The gates

**The build gate is `build_inline.py verify` with `canonicalize.py`.** It scores five checks and a pure split must pass all five: canonical sequence, decl-name set, byte-identity, header pairs, header placement. Byte-identity is scored because a check that's printed but left out of the verdict reads as coverage while providing none: `byte_ok` was wrong from v1.6's r004 to r023. `gather`'s raw line count (`raw_ok`) was the same defect from v1.6's r004 to r025. Both were found by trying to fool the gate.

```
python3 inlining/build_inline.py verify
Reconstitution-parity gate (pure split)
  canonical sequence : PASS (47463 non-blank lines vs reference 47463)
  decl-name set      : PASS (669 names)
  byte-identity      : exact
  header pairs       : PASS (89 headers)
  header placement   : PASS (0 misfiled)

GATE GREEN
```

**A gather uses `build_inline.py gather`.** Sequence and byte-identity differ on a relocation by design, so it scores the multiset, the decl-name set, the raw line count, and header placement, and reports the header-pair diff without scoring it. A good gather: GATHER GREEN, decl-set PASS at 669, raw line count PASS at 49,907, header placement 0 misfiled.

**A content edit uses `build_inline.py edit --files ... [--add ...] [--remove ...] [--shell]`.** It holds every undeclared file byte-identical to its anchor segment and scores the layout's freshness, the file set, the declared declaration delta, rule-1 shape per file, header placement, and the shell. It writes the in-scope diff to `inlining/out/edit-diff.patch`, which is the review artifact: read it. A good cut is EDIT GREEN with a diff that reads as the change intended and nothing else.

**Why the raw count is scored.** On a gather the other checks run on blank-stripped lines, so a dropped blank line is invisible to all of them. A cut that leaves a file ending on a blank loses that line to the assembler's `rstrip`. On a content edit, `edit`'s rule-1 check catches the same class on the raw text.

**Why `header placement` is separate from `header pairs`.** Pairs run on the assembled body, where file boundaries don't exist, so a header at the tail of one module labelling the head of the next pairs correctly. Placement reads each file alone and fails a section header with no declaration after it. v1.6's r025 swept eleven sheared section headers to the blocks they name, and its r026 replaced the last one; zero sheared headers remain.

**Gate teeth.** `python3 inlining/prove_gate_teeth.py` runs eighteen mutation probes, each injecting one defect into a throwaway copy of the current tree and asserting the right check goes red (or, for four of them, green with the right signal: the positive control, the two header shears that are reported rather than scored, and the declared shell change). Every probe must read OK; a MISS is a blind spot, and the fix goes in the check, never the probe. A probe that crashes, rather than reading OK or MISS, is a defect in the harness, and that one is fixed in the probe. Since 2026-10-24 `prove_gate_teeth.py` resolves its targets by role from the real tree (an ordinary module, a header whose one-line declaration can shear, a file that opens blank, header, blank), so a rename or a carve leaves it alone, and a role no module fits stops the run. Run it after any change to the assembler, the gate, or the tree's numbering. `tools/turnover/prove_teeth.py` is a different script: it probes the doc gate.

```
OK  drop one code line                 verify   OK  declared edit (positive control)   edit
OK  drop one BLANK line                verify   OK  edit outside declared scope        edit
OK  rename one declaration             verify   OK  undeclared declaration added       edit
OK  shear a section header             verify   OK  declaration lost in scope          edit
OK  shear a section header             gather   OK  declared file ends on a blank      edit
OK  misfile a header (byte-identical)  verify   OK  misfile a header (in scope)        edit
OK  drop one BLANK line                gather   OK  shear reported, not scored         edit
                                                OK  stale layout                       edit
                                                OK  file renamed (not an edit)         edit
                                                OK  shell changed, undeclared          edit
                                                OK  shell changed, declared            edit
```

**The doc gate** is `tools/turnover/check_docs.py`. It checks the six working documents (this file, the changelog, the roadmap, the doctrine, the manifest, the journal) against the tree and `docs/facts.json`. The stale-filename, line-count, published-figure, and retired-anchor checks read only each document's live region (the changelog's newest session block, the roadmap's newest dated block, the journal's newest entry, the other three whole); the em-dash, banned-phrase, table, and required-string checks read whole files. It checks derived tree figures, newly authored em dashes and banned phrases against `docs/.turnover-baseline.json`, stale `NN_` filenames, per-file line counts quoted in prose, table shape, published figures, retired anchors named as live, required strings, carve-span tiling, and `file:line` assertions against the source. `prove_teeth.py` re-proves it with eleven probes after any change to the checker or the facts. What it does not cover still needs a read: directional and causal claims, whether a doctrine entry is right rather than merely numerate, and anything absent from `facts.json`. One known blind spot, narrowed on 2026-10-24: the retired-anchor check excuses a retired anchor whose own sentence (or table cell) carries a history marker (an arrow, or any of retired, anchored, rotated, rotation, history, stale, superseded, "was the", formerly, "no longer", or a dated "at rNNN"). Until then one marker anywhere on a line excused every anchor on it. A live claim and a marker can still share a sentence, so read every line that names an anchor by hand at each rotation. And the r-counter starts over with each line, so one file name can be two lines' anchors: `reference-r018-body.jsx` was v1.6's r018 anchor and then v1.7's, and while it was active the check couldn't tell a sentence about the old one from one about the active anchor (found at r018's turnover, when `prove_teeth.py`'s two anchor probes, which named the old one, read MISS). v1.7's r020 anchor shares its name with the anchor v1.6's r020 gather rotated to, so the check is blind the same way while it's active.

## Procedures

Each is stated here once.

**Content cut.** Script the change into `inlining/cuts/v<version>_r###_description.py`: the cut's tag, then a snake_case description (`v1.7_r001_text_fixes.py`; v1.6's scripts keep their bare `r###_` names). String-anchor it, every anchor asserted to occur exactly once, and have it find the repository by what it holds, never by counting folders or by an absolute path: `ROOT = next(p for p in Path(__file__).resolve().parents if (p / 'cartulary-src').is_dir())`. No hand edits to the tree, so a wiped sandbox can replay from the repository: every script from v1.6's r031 on reproduces its tag exactly when run against the tag before it (checked 2026-10-23, and against GitHub's tags on 2026-10-24), except where two cuts share one tagged commit: v1.6's r039 and r040 are both tagged on `0eab394`, and its r048 and r049 on `547926f`, so r039 and r048 reproduce their own commits, `d67eb3f` and `fd59f72`, and r040 and r049 replay from those. v1.6's r025 through r030, which came in with the tree already past them, can't be replayed at all. A cut script is not idempotent: to replay it, `git checkout <prior sha> -- <files>` first. That command stages the old content as well as writing it, so before amending a cut that was replayed this way, `git add` every file in its scope; then `git status` is clean and `git diff --stat <prior sha> HEAD` lists the whole cut (v1.7 r001's first amend added only the two new changes and committed r000's text for the other six files, caught by `git status` before anything left the sandbox). Then `build_inline.py edit` with the declared files and declarations, and read the diff; if the script also edits `site/`, read `git diff -- site/` too, because `edit` never sees it. One cut per r-number.

**Pure carve** (proven on 22 carves). Locate the module's members by name; confirm they're contiguous (gather first, as its own cut, if they aren't); print the seam lines and read them before slicing; slice under the boundary rules; write the new file or directory, reflowing the downstream `NN` prefixes so assembly order stays contiguous; `verify` must pass all five checks; `working` and the parse gate; the rebuilt `working` must hash equal to the artifact last passed (`verify` never reads `shell.html`, so the hash is what proves nothing outside the tree moved); `freeze` with no name rewrites the active anchor's layout for the new file set; `verify` again. With the byte-identity and the hash both holding, the carve changed no byte of the product: it owes no browser pass and does not rotate the anchor. When several carves share one arc and their spans are published, carve back to front, so every span ahead keeps its line numbers.

**Boundary rules, all earned.**
1. Boundary blanks lead the following file; no file may end on a blank. The assembler's `rstrip` eats a trailing blank. Canonical sequence won't catch it; byte-identity will, and on a content edit `edit`'s rule-1 check will.
2. The body's trailing newline stays in the shell, not in the last module.
3. A section header travels with its block.
4. A doc comment travels with its declaration.
5. A doc comment can sit behind a blank line, which defeats a walk-back over `//` lines and produces a plausible wrong span. Print the lines around every cut point; a computed span is a hypothesis and the seam lines are the evidence.

**Gather.** Its own r-number: relocate the scattered members into one contiguous run (position only, no code), `gather`, then `working` and the parse gate, stop for the browser pass, then `freeze r###`, `verify`, and the hash check. One gather at a time.

**When a browser pass is owed.** Every cut that changes the assembled bytes owes one: every gather and every content cut. A pure carve owes nothing only when both hold: byte-identity against the active anchor is exact, and the rebuilt `working` hashes equal to the artifact last passed. The first proves the tree reassembles; only the second covers `shell.html`, which `verify` never reads. Keep that exception narrow.

**Rotation.** `build_inline.py freeze r###` writes the assembled body as the new anchor with its layout, confirms frozen equals assembled, and deletes the retired pair. Then `verify` (byte-identity exact) and rebuild `working`: its hash must equal the artifact that was passed. That check catches a rotation that froze the wrong body, and it's the recovery check after a lost sandbox. Never freeze a body that hasn't passed.

**Eval-order check before any relocation.** What matters is definition time against call time, not source order. Function declarations hoist. A const arrow may sit above its callees when the reference is inside its body; an initializer that runs at evaluation (`const X_SET = new Set(X_TYPES)`) keeps its dependency above it. Assembly-order inversions on record, all call-time and safe: `makeInitialState` calls `migrate`; `12_trunk` calls into `24_ephemeris/`; `08_export-layer` calls cartographia's renderer.

**Turnover.** After every cut, and at any session close that changed the record: edit the documents in place to match the tree, run the doc gate (DOCS GREEN) and `prove_teeth.py` (all eleven OK; it exits non-zero on a MISS), sweep every added line for em dashes and banned phrases, commit, push, and wait for CI on the head commit. After a rewrite that shrinks a document, rebaseline with `check_docs.py --docs docs --src cartulary-src --baseline docs/.turnover-baseline.json` once a Python sweep shows nothing newly authored: the gate counts against the baseline, so a stale higher count lets new dashes through. The em-dash probe writes into this file, whose baseline of 3 is the three entity forms named in the em-dash rule under Working with Drak; a rewrite that drops that line needs a rebaseline before the probe bites again. `--write-facts FILE` regenerates the derived section of `facts.json`; published figures, assertions, spans, and required strings are edited by hand when the documents change what they state. The six documents' roles and rules are in `tools/turnover/conventions.md`.

**Finals** (release prep only, never per cut). Extract each tarball in `deps/` into `inlining/node_modules/` (scoped packages under `@babel/` and `@fontsource/`; the exact loop is in the repository README), then `python3 inlining/build_inline.py finals`, then `node inlining/validate_html.js` on each output. `finals` inlines the libraries and both fonts, precompiles the JSX, and swaps the shell head's CDN tags (d3 7.8.5, babel 7.23.5, the dev form) for pinned d3 7.9.0 and babel-standalone 7.29.4. Do not "fix" the shell head: the zero-external-URL rule is about the built finals. Since 2026-10-24 `finals` writes its temporary JSX into a fresh directory from Python's `tempfile` rather than to `/tmp`, and reads and writes the build as UTF-8 bytes. Finals are never committed.

**Shipping.** The ship gate is Drak's pass on the finals themselves, never on the working file: the precompiled build is its own code path (JSX compiled ahead of time, libraries and fonts inlined), and the working file exercises none of it. Before his pass, run the headless probes against the precompiled final. The checklists that gated v1.6 and v1.6.1 are `docs/release-notes/v1.6/finals-pass.md` and `docs/release-notes/v1.6.1/finals-pass.md`; write the next one from them. A defect the pass finds is a cut before ship, not a note in the release. Then: the zip (`Cartulary_v<version>.zip`: both finals and the zip README, which v1.6 carried as `README.md`; v1.6.1's, packed by Drak, also carried its patch notes and named the README `README_v1.6.1.md`); the itch upload with the page text and the devlog from `docs/release-notes/v<version>/`; the site deploy if `site/` moved; the ship turnover (the version line to SHIPPED, the finals' hashes, the date, and the line's last revision tag, which names the tree the finals came from); and the `v<version>_Release` tag on the ship-turnover commit, which Drak pushes. To read the live itch page, use a browser: WebFetch answers for drakhanas.itch.io/cartulary from a stale copy that knows only v1.0, every time (Drak, 2026-10-24).

**Tags.** Two forms. A revision's tag is `v<version>_r###`: a lower-case `v`, the line's version with its dot, then `_r` and the zero-padded counter, the same pair a working copy's file name carries (`v1.7_r001`). A release's tag is `v<version>_Release`, with a capital R (`v1.7_Release`). No spaces; git refuses them. A revision tag marks a passed state and goes on the commit CI went green on, which after a cut is its turnover commit; a bare freeze commit is doc-gate red until its turnover lands. The previous line's shipped tree is the new line's r000 and is never tagged (v1.7's r000 is the tree `v1.6.1_Release` marks), so a line's first tag is its r001. A patch continues its line instead of opening one: v1.6.1 bumps `VERSION` to `'1.6.1'` but keeps v1.6's count, so its first cut is r052, tagged `v1.6.1_r052`, the first tag in this form, and it ships with its own release tag, `v1.6.1_Release` (Drak, 2026-10-23). The release tag goes on the ship-turnover commit once CI is green there; the ship turnover changes only documents, so that commit builds the same finals as the line's last revision tag. A tag push re-runs CI on the tagged commit. The session's git credential refuses tag pushes, so Drak tags from his clone with the three lines `git pull` / `git tag v1.7_rNNN <sha>` / `git push origin v1.7_rNNN`, and the same three with `v1.7_Release` at the ship. The tags from before the rule (2026-10-23) keep their names: `r030` through `r051` on the v1.6 line's passed states, and `v1.6` on `8554fdf`, the v1.6 ship turnover. The anchor's name stays bare: `freeze` takes `r###` and names it `reference-r###-body.jsx`, which can't collide because only one exists at a time. Cut scripts carry the tag (Content cut).

**Opening and closing a line.** A line closes when the finals are live (the upload, not the build). At the close, the changelog freezes to `changelog-v<version>.md`, this handoff freezes to `handoff-v<version>.md`, and the version's plan and session blocks move from the roadmap to `roadmap-archive.md`, all verbatim; the live files start over with current state. A patch closes without a freeze: its record stays in the active changelog's between-lines section, its release text goes to `docs/release-notes/`, and the version line records the ship, as v1.6.1's did. A line opens with the `VERSION` bump, which puts the r-counter at r000: the previous line's tree as shipped, which takes no tag. A patch's bump (`1.6.1`) keeps the line's count instead (see Tags). The first product edit is r001, the line's first tag, and it flips the export's version literals. From the bump on, a bare r-number in the live documents means the new line's, so the opening turnover writes the version into the closed line's that remain in current-state text: this handoff and the roadmap's standing sections (`v1.6 r036`). Dated history keeps its numbers as written, read in the line its date and session name: the doctrine's entries, the manifest's carve record, the changelog, the journal, and the roadmap's session blocks, the way v1.6's opening left v1.5's (settled at v1.7's opening, 2026-10-24).

**Commits.** One commit per gate-green step, with the revision in the message for cuts, written as its tag (`v1.7_r001: ...`, `Freeze v1.7_r001`, `Turnover v1.7_r001`); a freeze is a commit and a turnover is a commit. ## Architecture

**Glossopoeia, Ephemeris, and Cartographia are views with their own state slices, not sets of templates.** Each owns a `state.*` slice, registers through the node-source registry so it's graphable in Concordance, and has `migrate()` backfill its arrays; never model these as `BUILTIN_TEMPLATES` entries. Glossopoeia and Cartographia records are shaped `{ id, name, tags:[], fields:{} ... }` and render their fields through `EntryForm` with a per-type `*Schema()` function. **Ephemeris is the exception:** a celestial body is a flat record (`makeNewCelestialBody` in `24_ephemeris/`) with its own editor rather than `EntryForm`, and its `tags` is a comma-separated string, split on read. Code that assumes `tags` is an array breaks on bodies, the same family of mistake as the v1.3 tags crash.

- **`state.cartographia`** is a flat array of map records `{ id, name, tags:[], fields:{}, mapData:{ image, pins, drawing }, updatedAt }`, with the fixed field ids `cart-fld-description`, `cart-fld-scope-region`, `cart-fld-notes` rendered through `cartographiaMapSchema()`. `drawing` is `{ width, height, background, layers }`; a layer is vector (shapes) or raster (one bitmap, stored like a map image: a folder file `<map id>-<layer id>.<ext>` or a data URL). `ensureMapData` normalizes on every load and coerces rather than throws. Maps register as `SYNTH_TPL_MAP` with outbound pin edges and, since v1.7's r003, `refEligible:true`: a field can target maps on purpose (the template builder always offered Map), a reference to a map shows its name and opens it, and deleting a map clears the references to it after the confirmation counts them (`mapDeleteMessage`, `18_cartographia/04_index`). The JSON shapes are in the in-app help's JSON Save File Schema topic.
- **`state.mapStamps`**: stamps imported from stamp packs, world-scoped, ids namespaced by pack (`forest__pine`), every SVG body sanitized on import and again on load.
- **`state.glossopoeia`**: 21 record arrays plus `workspaceNotes` and `ui`, records `{ id, langId, name, tags:[], fields:{} }`. The schemas are in the frozen design docs `docs/glossopoeia-design-handover.md` and `docs/glossopoeia-phase-two.md`.
- **`canvasSlot`.** `EntryView` and `EntryForm` take an optional canvas node rendered above the fields; Cartographia fills it, since v1.7's r007 a corpus's page puts its reading order in `EntryView`'s, since r008 a story's page puts its tabs in both, since r009 the People tab puts its lists in `EntryView`'s, and since r011 the Outline tab its tree. Reuse it for any future canvas-over-form view.
- **Panels** (since v1.7's r008). `EntryView` and `EntryForm` draw a template's fields in panels when they're given `panels` (`[{ id, label }]`) and a field names its panel (`field.panel`): the fields in no panel first, then each panel under a heading that folds it (`fieldPanelSegments`, `FieldPanelHeading`), so a half-width pair never straddles a heading. The folds are the caller's (`foldedPanels`, `onTogglePanel`). Without panels both draw as before. In view an empty field doesn't show, so an open panel with nothing filled in says so.
- **`migrate()`'s entry-ref cleanup** (near its end) checks every top-level field with a target list or filters: an entry reference survives if the entry exists, its template is allowed, and it passes the field's filters, and since v1.6.1's r052 a reference to a registered record (a body, a Glossopoeia record, a map) survives if the record's source is among the field's targets. Group subfields are never cleaned. Anything new that a reference can point at has to be taught to this check, or the load erases it.
- **A reference field keeps its targets twice:** names (`refTemplate`, `refTemplates`), the form built-in definitions and template and pack files carry, and ids (`refTemplateId`, `refTemplatesId`), which the picker reads and the template builder edits. `resolveTemplateRefs` derives the ids from the names when it runs: on a load that backfills a built-in template or field, merges duplicate templates, or repairs a showWhen, and in session on a pack import, a template restore, or a reset to built-in. That isn't every load, though the v1.5 conversions' comments said it was until v1.7's r004. Since v1.7's r002 it keeps every id that still resolves, and `syncRefTargetNames` makes a field's names follow its ids, run by `saveTemplate` on the template saved and once per world by `migrate()`; both resolve names through `refTargetIndex` (all three in `01_builtin-templates`). A field holding an id that resolves to nothing, a deleted template say, is left alone by the sync. A migration that changes targets edits both lists itself: calling `resolveTemplateRefs` from one re-derives every field in the world.
- **A migration that retires a template points the fields that list it at where its records went** (since v1.7's r004). `retargetRetired` (`10_migrate`) replaces the template's id and name together: Astronomical Body with the body source, Language / Glossary with ConLang (and with ConLang and Lexeme in a field that takes several templates, since its words became lexemes), a map template with the maps. The v1.5 conversions call it with the template's own id. The map promotion runs before r002's name sync, so it notes the templates it removes (`promotedMapTemplates`) for the repair instead. The repair runs once per world (`state.migrations.retiredTargetsRepairedV17`), right after the sync and before anything in the load re-resolves: it knows the three retired built-ins' ids by their shape (`tpl-astronomical-body-`, `tpl-language-glossary-`, or `tpl-map-`, then four characters) once nothing has them, and it rebuilds a multi-target list the Language / Glossary supersede cleared from its names, adding Lexeme and every target the field already points at, so the cleanup deletes nothing. A map template of the user's own is known only to the load that promotes it. A future migration that retires a template calls `retargetRetired` in the same load, or the cleanup deletes the references to its records.
- **What a reference shows** (since v1.7's r003): `resolveRefTarget` (`13_form-engine-display`) finds a value's target among entries, bodies, and the registered records for the entry view, its group subfields, and its grid cells, and says whether a click can open it. Entries, bodies, and maps open (`openEntryFromAnywhere` knows those three, since r007 a Fabula corpus or story, since r009 a cast record, an arc, or a relationship, since r011 an act, a chapter, or a scene, since r013 a plot point or a promise, and since r014 a research note, from a chip or from Concordance; `fabulaRecordOpens` says which of Fabula's sources open, and since r012 a chip for an act, a chapter, or a scene reads its position first, drawn quieter than its name, from the `place` the story's nodes carry); a Glossopoeia record is a plain chip titled with its type, since nothing opens one yet. The exports carry the registered records in their context (`registeredNodeIndex`, `08_export-layer`): the Markdown exports write the name, and the HTML export's `refLinkHtml` links an entry or a map to its article and writes a body or a Glossopoeia record as its name. Concordance's hover pane names them too. Deleting a Glossopoeia record still leaves entry references to it behind (on the roadmap).
- **A multi-select's Other** (since v1.7's r005): with `otherTextField` set, `MultiSelectEditor` (`14_form-engine-edit`) shows a box under the options, and a value typed there is stored as one more string in the field's array; one that matches an option, ignoring case, picks the option instead, and one that matches a value already picked changes nothing. So a value that isn't among the options is the user's own in a field that allows Other, and in one that doesn't it shows dashed, the way a pick whose option was deleted does. A dropdown's Other stores `{ value, customText }` instead. Four fields in Fabula's lists use it.
- **`state.fabula`** (since v1.7's r006) holds an array per record kind and `schemas`, one per kind. `FABULA_KINDS`, beside the node-source registry, names each kind's array, sentinel id, label, and color. Since r007 each kind is registered, not eligible as a reference target, so no template builder offers it (the builder lists eligible sources only), and grouped, so Concordance shows all eleven behind one Fabula toggle; a kind's nodes are its records, and its edges a corpus's stories and, since r009, a story's threads and themes, a cast record's character, an arc's cast, and a relationship's two, since r011 a scene's POV, participants, setting, and threads, since r013 a plot point's scene and threads and a promise's setup and payoff scenes and threads, since r014 a research note's entries and scenes, since r015 a scene's motifs, and since r017 a link field of the user's own (`fabulaRegistryInstances`, `fabulaRegistryEdges`). `fabulaSeedSchemas` builds the schemas from the passed tables against the world's templates, and `ensureFabulaSlice`, which `migrate()` runs last, keeps the arrays and seeds a kind's schema when it's missing or from an older seed (`FABULA_SCHEMA_SEED`, 4 since r017, when the core list caught up with what features read; 3 at r011, when a beat took What Happens and a chapter's and a scene's Status and a scene's Beats became core; 2 at r009, when an arc's Cast took more than one) and not marked `edited`, and since r017 brings an edited one's core fields up to the seed on every load (below); a newer seed is left alone. When a seed replaces a schema, a reference the new seed takes more than one of keeps what it held, as a list of one, and in an edited schema only where the field is core. A change to the seed raises its number, or every world keeps the schema it has. The seeded reference fields keep names and ids as a template's do, but `resolveTemplateRefs`, `syncRefTargetNames`, and r004's retarget repair don't reach them on a load (since r017 the builder's Save syncs the names of the kind it saves), so a migration that renames or retires a template has to treat Fabula's schemas itself. A target the world doesn't have keeps its name and no id, and an empty id list reads as any template to the picker. Since r008 a form works a reference field's targets out each time it's drawn (`fabulaLiveFields`, inside `fabulaTemplate`): its stored ids that still exist plus whatever templates its names find, writing nothing back, and a field that finds none offers nothing, says which template is missing, and offers to restore a missing built-in (Drak, 2026-10-25). A link to Fabula's own records offers only the story's (`fabulaStoryNodes`) and says so when the story has none of the kind, and since r012 a link to acts, chapters, or scenes lists them in the outline's order, each with its position (`keepOrder`, which `EntryRefEditor` honors where it sorts every other picker by name). Since r013 a scene's, a plot point's, or a promise's Threads lists the story's own threads first, when it has any, under a heading of their own, and the rest under another (`firstIds`, `firstLabel`, and `restLabel`, which `EntryRefEditor` groups), and a plot point's Slot offers the story's slots (`fabulaStorySlots`) and, after a structure change, the one it holds. Since r015 a scene's Motifs lists the story's own themes first the same way.
- **Fabula's screen** (since v1.7's r007) follows the map page's pattern. `App` holds `activeCorpusId`, null for the index, and `corpusDraft`, a working copy of the corpus in edit, committed on Save, which `isDraftDirty` and `confirmDiscardDraft` know. A corpus's fields render through `EntryForm` and `EntryView` from `fabulaTemplate`, the world's stored schema or the seed. The reading order, the Corpus dropdown, renames, new stories, and deletes change `state.fabula` at once, with no edit step. Since r008 a story has a page of its own: `activeStoryId` draws it over the page it was opened from (`activeCorpusId`, a corpus's page or the index), which its Back returns to, and `storyDraft` is the Story record in edit. The Story tab's folds are `prefs.fabulaFolds`, the display settings', one set for every story. `openEntryFromAnywhere` opens a corpus on its page and a story on its own, over its corpus's page or the index. Since r009 the story's tabs switch (`storyTab`), and a cast record, an arc, or a relationship has a page of its own (`FabulaRecordPage`), drawn over the story's page, whose People tab lists them (`FabulaPeopleTab`): `activeRecord` (`{ kind, id }`) is the record, `recordDraft` the record in edit (one whose id isn't in its slice yet is new), and `fabulaBack` the pages Back returns through, a tab of the story or another record. `openEntryFromAnywhere` opens a record over the page it was clicked from when that's in the same story, and otherwise over the story's tab that lists it, People or, since r011, Outline (`fabulaTabOf`). ## Carry-forward facts

- **Zero network requests is a rule** (Drak, 2026-10-23, v1.6 r051): a request anywhere in the application is a defect to cut, not a feature with a fallback. The SVG download embeds the map font from the page's own inline stylesheet; the development build, whose head loads fonts by link, falls back to the viewer's serif in the download, and that's expected.
- **Concordance opens with an empty template filter** (v1.5 r134, by design); **all** and **none** recover it. Don't "fix" it back to all-on.
- **Synthetic-node positions persist** across reload, with force containment keeping the graph compact (v1.5 r131-r132).
- **v1.6 r001 edge cases, accepted:** a map's `calendarId` is dropped; an unsaved map edit is lost on reload; an imported `.template.json` with `kind:"map"` is self-healed by `migrate()`.
- **Pre-v1.6 em dashes are frozen.** The rule governs newly authored text only. At the session-16 count the source carried 1,111 older ones, 283 of them in the in-app help, and none get swept.
- **The undo history covers the map editor only.** Everywhere else, Version History and the exported `.json` are the safety net.
- **The auto-save writes 250 ms after the last change** (`12_trunk`), and the write itself takes a moment more, so a probe's read of the saved world waits it out (r011's waits 600 ms; reading and reloading too soon cost its first full run 13 checks), and a reload or a closed tab inside the window loses the last change (roadmap, Tolerated). The warning before unload covers an open draft only, and its comment says 500 ms.
- **Nine browser probes at once are too many for this sandbox.** At r012 two of nine crashed, one on a 30-second load timeout and one when its page died, and both ran clean alone; run the regression probes a few at a time, and rerun a crash alone before reading it as a result.
- **A picker's option is an entry's bare name unless its field lists more than one template**, when the template's name follows in parentheses (`formatEntryLabel`, inside `EntryRefEditor`); a field open to any template lists bare names. r012's K3 and r015's P1 each expected the other form on their first run.
- **Wait for probes by their processes.** Start them from one shell, each in the background, and `wait`. Two other waits have hung: at r012 a loop on `pgrep -fc 'node probe_'` also counted the shell running the loop, whose command line held the pattern, and at r013 a loop waiting for each run's total line never ended, because one mutant's run stopped before printing it, as a mutant's may.
- **A probe's default timeout reaches navigation too.** Playwright's `setDefaultTimeout` sets the wait for `goto` along with every click and selector, and the working build compiles its JSX in the page, so it can take longer to load than a click should wait. r016's mutant runs, with a five-second default, failed at their first `goto` until the probe set `setDefaultNavigationTimeout` apart from it.
- **The session's file-writing tool turns `\uXXXX` escapes into the characters.** r013's first assembly of its cut, written through it, put a literal ·, ×, the arrows, and non-breaking spaces into code that writes them as escapes. Assemble a cut's source with Python, or read its non-ASCII lines before running the cut.
- **The default calendar is Common Year** (v1.7 r001): the Gregorian months with no leap rule. Worlds saved before keep the name they stored, often Gregorian, by Drak's call; nothing renames a stored calendar.
- **This environment's stop hook asks for every commit to be pushed at every stop** (`~/.claude/stop-hook-git-check.sh`, which also flags uncommitted and untracked files and unsigned commits). A cut stays local through Drak's pass anyway: pushing it puts `main` out of step with the anchor, and CI's `verify` fails until the freeze lands. Answer the hook in a line and stop; it doesn't fire twice in a row. v1.6's session 19 met it from r031 on and never wrote it down, so session 20 announced it as news.
