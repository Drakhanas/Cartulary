## The tree

The working HTML is not the source. The source is:

- `cartulary-src/shell.html`: the page scaffolding, with one `@@CARTULARY_BABEL_BODY@@` sentinel where the babel body goes. The body's trailing newline belongs to the shell.
- `cartulary-src/modules/NN_name.jsx`: a flat module. `NN` is the two-digit assembly order; `name` is the module.
- `cartulary-src/modules/NN_name/NN_part.jsx`: a directory module. The directory carries the outer prefix and each part its own `00`-based one. Five exist: `18_cartographia/`, `21_stemma/`, `23_glossopoeia/`, `24_ephemeris/`, and `28_fabula/`.
- `cartulary-src/reference-r044-body.jsx`: the frozen parity anchor, active as of v1.7's r044. Found by glob, never named in code: exactly one `reference-r###-body.jsx` may exist, and the gate refuses on zero or two. Its companion `reference-r044-layout.json` holds the per-file line counts that segment it, its sha256, and the shell's text and sha256; `edit` needs it and `freeze` writes it.

## The gates

**The build gate is `build_inline.py verify` with `canonicalize.py`.** It scores five checks and a pure split must pass all five: canonical sequence, decl-name set, byte-identity, header pairs, header placement. Byte-identity is scored because a check that's printed but left out of the verdict reads as coverage while providing none: `byte_ok` was wrong from v1.6's r004 to r023. `gather`'s raw line count (`raw_ok`) was the same defect from v1.6's r004 to r025. Both were found by trying to fool the gate.

```
python3 inlining/build_inline.py verify
Reconstitution-parity gate (pure split)
  canonical sequence : PASS (53507 non-blank lines vs reference 53507)
  decl-name set      : PASS (847 names)
  byte-identity      : exact
  header pairs       : PASS (103 headers)
  header placement   : PASS (0 misfiled)

GATE GREEN
```

**A gather uses `build_inline.py gather`.** Sequence and byte-identity differ on a relocation by design, so it scores the multiset, the decl-name set, the raw line count, and header placement, and reports the header-pair diff without scoring it. A good gather: GATHER GREEN, decl-set PASS at 847, raw line count PASS at 56,212, header placement 0 misfiled.

**A content edit uses `build_inline.py edit --files ... [--add ...] [--remove ...] [--shell]`.** It holds every undeclared file byte-identical to its anchor segment and scores the layout's freshness, the file set, the declared declaration delta, rule-1 shape per file, header placement, and the shell. It writes the in-scope diff to `inlining/out/edit-diff.patch`, which is the review artifact: read it. A good cut is EDIT GREEN with a diff that reads as the change intended and nothing else.

**Why the raw count is scored.** On a gather the other checks run on blank-stripped lines, so a dropped blank line is invisible to all of them. A cut that leaves a file ending on a blank loses that line to the assembler's `rstrip`. On a content edit, `edit`'s rule-1 check catches the same class on the raw text.

**Why `header placement` is separate from `header pairs`.** Pairs run on the assembled body, where file boundaries don't exist, so a header at the tail of one module labelling the head of the next pairs correctly. Placement reads each file alone and fails a section header with no declaration after it. v1.6's r025 swept eleven sheared section headers to the blocks they name, and its r026 replaced the last one; zero sheared headers remain.

**Gate teeth.** `python3 inlining/prove_gate_teeth.py` runs eighteen mutation probes, each injecting one defect into a throwaway copy of the current tree and asserting the right check goes red (or, for four of them, green with the right signal: the positive control, the two header shears that are reported rather than scored, and the declared shell change). Every probe must read OK; a MISS is a blind spot, and the fix goes in the check, never the probe. A probe that crashes, rather than reading OK or MISS, is a defect in the harness, and that one is fixed in the probe. Since 2026-10-24 `prove_gate_teeth.py` resolves its targets by role from the real tree (an ordinary module, a header whose one-line declaration can shear, a file that opens blank, header, blank), so a rename or a carve leaves it alone, and a role no module fits stops the run. Run it after any change to the assembler, the gate, or the tree's numbering. `tools/turnover/prove_teeth.py` is a different script: it probes the doc gate.

```
OK  drop one code line                 verify   OK  declared edit (positive control)   edit
OK  drop one BLANK line                verify   OK  edit outside declared scope        edit
OK  rename one declaration             verify   OK  undeclared declaration added       edit
OK  shear a section header             verify   OK  declaration lost in scope          edit
OK  shear a section header             gather   OK  declared file ends on a blank      edit
OK  misfile a header (byte-identical)  verify   OK  misfile a header (in scope)        edit
OK  drop one BLANK line                gather   OK  shear reported, not scored         edit
                                                OK  stale layout                       edit
                                                OK  file renamed (not an edit)         edit
                                                OK  shell changed, undeclared          edit
                                                OK  shell changed, declared            edit
```

**The doc gate** is `tools/turnover/check_docs.py`. It checks the six working documents (this file, the changelog, the roadmap, the doctrine, the manifest, the journal) against the tree and `docs/facts.json`. The stale-filename, line-count, published-figure, and retired-anchor checks read only each document's live region (the changelog's newest session block, the roadmap's newest dated block, the journal's newest entry, the other three whole); the em-dash, banned-phrase, table, and required-string checks read whole files. It checks derived tree figures, newly authored em dashes and banned phrases against `docs/.turnover-baseline.json`, stale `NN_` filenames, per-file line counts quoted in prose, table shape, published figures, retired anchors named as live, required strings, carve-span tiling, and `file:line` assertions against the source. `prove_teeth.py` re-proves it with eleven probes after any change to the checker or the facts. What it does not cover still needs a read: directional and causal claims, whether a doctrine entry is right rather than merely numerate, and anything absent from `facts.json`. One known blind spot, narrowed on 2026-10-24: the retired-anchor check excuses a retired anchor whose own sentence (or table cell) carries a history marker (an arrow, or any of retired, anchored, rotated, rotation, history, stale, superseded, "was the", formerly, "no longer", or a dated "at rNNN"). Until then one marker anywhere on a line excused every anchor on it. A live claim and a marker can still share a sentence, so read every line that names an anchor by hand at each rotation. And the r-counter starts over with each line, so one file name can be two lines' anchors: `reference-r018-body.jsx` was v1.6's r018 anchor and then v1.7's, and while it was active the check couldn't tell a sentence about the old one from one about the active anchor (found at r018's turnover, when `prove_teeth.py`'s two anchor probes, which named the old one, read MISS). v1.7's r020, r021, and r022 anchors shared their names with the anchors v1.6's gathers of those numbers rotated to, so the check was blind the same way while each was active; v1.7's r023 and r024 anchors share their names with none, since v1.6's r023 and r024 were pure splits, so the check sees them.

**CI.** `.github/workflows/` runs verify, working, the parse gate, the gate teeth, the doc gate, and the doc-gate teeth on every push and on every tag push, with nothing fetched from the network. Every step fails the run on a miss; the doc-gate teeth have since 2026-10-23, when `prove_teeth.py` started exiting non-zero on a MISS (before that it only printed one).

## Procedures

Each is stated here once.

**Content cut.** Script the change into `inlining/cuts/v<version>_r###_description.py`: the cut's tag, then a snake_case description (`v1.7_r001_text_fixes.py`; v1.6's scripts keep their bare `r###_` names). String-anchor it, every anchor asserted to occur exactly once, and have it find the repository by what it holds, never by counting folders or by an absolute path: `ROOT = next(p for p in Path(__file__).resolve().parents if (p / 'cartulary-src').is_dir())`. No hand edits to the tree, so a wiped sandbox can replay from the repository: every script from v1.6's r031 on reproduces its tag exactly when run against the tag before it (checked 2026-10-23, and against GitHub's tags on 2026-10-24), except where two cuts share one tagged commit: v1.6's r039 and r040 are both tagged on `0eab394`, and its r048 and r049 on `547926f`, so r039 and r048 reproduce their own commits, `d67eb3f` and `fd59f72`, and r040 and r049 replay from those. v1.6's r025 through r030, which came in with the tree already past them, can't be replayed at all. A cut script is not idempotent: to replay it, `git checkout <prior sha> -- <files>` first. That command stages the old content as well as writing it, so before amending a cut that was replayed this way, `git add` every file in its scope; then `git status` is clean and `git diff --stat <prior sha> HEAD` lists the whole cut (v1.7 r001's first amend added only the two new changes and committed r000's text for the other six files, caught by `git status` before anything left the sandbox). Then `build_inline.py edit` with the declared files and declarations, and read the diff; if the script also edits `site/`, read `git diff -- site/` too, because `edit` never sees it. Then `working` and the parse gate, in that order (`check.js` reads the working HTML, which `edit` doesn't write), and stage the working HTML as `Cartulary_v<version>_Working_r###_(description).html`. Run a headless probe of the change where one can be written (the working build's head loads React, Babel, marked, d3, and JSZip from cdnjs and its fonts from Google, none of which the sandbox reaches, so a probe routes those requests to the tarballs in `deps/` and answers the font requests empty; r001's through r009's and r011's through r019's did, through Playwright, and a read of the saved world waits out the auto-save, as Carry-forward facts says), and commit the cut locally; it is pushed only after the pass, the freeze, and the turnover. **Stop for Drak's browser pass**, naming the concrete things to check and which file to open. After the pass: `freeze r###`, `verify`, rebuild `working` and confirm its hash equals the file he passed, commit the freeze, then the turnover. A change folded into a cut after its pass changes the bytes, so it owes a pass of its own; diff the new working build against the passed one and name exactly what changed (r001's builder hint, one line). A cut that changes what `migrate()` does to a stored world gets a probe that saves a world with the previous build, loads it with the new build from the same file path, and runs the same world through the previous build as well, as a control: r002's control failed 21 of the 27 load checks the cut passed, which is what showed the probe reached the code it meant to test. When the change is about worlds an older release made, the probe builds its world in that release's own final and walks it through the real builds between: r004's came from the v1.4 final in Drak's archive (sha256 `755e95a722506f5e`, as `docs/release-notes/README.md` records), which throws one error of its own on each reload, from its unload handler (fixed in v1.6's r046). Judge the control by the new build's expectations as well, so the count of checks it fails is the defect's reach, not the account's. A cut that adds to the save file also checks the way back: a world it saved, opened and saved by the last release's final rebuilt from its tag, comes back with the addition intact (r006's used the v1.6.1 final, which rebuilds to its shipped hash, `d9125ed013be5641`). One cut per r-number.

**Pure carve** (proven on 24 carves). Locate the module's members by name; confirm they're contiguous (gather first, as its own cut, if they aren't); print the seam lines and read them before slicing; slice under the boundary rules; write the new file or directory, reflowing the downstream `NN` prefixes so assembly order stays contiguous; `verify` must pass all five checks; `working` and the parse gate; the rebuilt `working` must hash equal to the artifact last passed (`verify` never reads `shell.html`, so the hash is what proves nothing outside the tree moved); `freeze` with no name rewrites the active anchor's layout for the new file set; `verify` again. With the byte-identity and the hash both holding, the carve changed no byte of the product: it owes no browser pass and does not rotate the anchor. When several carves share one arc and their spans are published, carve back to front, so every span ahead keeps its line numbers.

**Boundary rules, all earned.**
1. Boundary blanks lead the following file; no file may end on a blank. The assembler's `rstrip` eats a trailing blank. Canonical sequence won't catch it; byte-identity will, and on a content edit `edit`'s rule-1 check will.
2. The body's trailing newline stays in the shell, not in the last module.
3. A section header travels with its block.
4. A doc comment travels with its declaration.
5. A doc comment can sit behind a blank line, which defeats a walk-back over `//` lines and produces a plausible wrong span. Print the lines around every cut point; a computed span is a hypothesis and the seam lines are the evidence.

**Gather.** Its own r-number: relocate the scattered members into one contiguous run (position only, no code), `gather`, then `working` and the parse gate, stop for the browser pass, then `freeze r###`, `verify`, and the hash check. One gather at a time.

**When a browser pass is owed.** Every cut that changes the assembled bytes owes one: every gather and every content cut. A pure carve owes nothing only when both hold: byte-identity against the active anchor is exact, and the rebuilt `working` hashes equal to the artifact last passed. The first proves the tree reassembles; only the second covers `shell.html`, which `verify` never reads. Keep that exception narrow.

**Rotation.** `build_inline.py freeze r###` writes the assembled body as the new anchor with its layout, confirms frozen equals assembled, and deletes the retired pair. Then `verify` (byte-identity exact) and rebuild `working`: its hash must equal the artifact that was passed. That check catches a rotation that froze the wrong body, and it's the recovery check after a lost sandbox. Never freeze a body that hasn't passed.

**Eval-order check before any relocation.** What matters is definition time against call time, not source order. Function declarations hoist. A const arrow may sit above its callees when the reference is inside its body; an initializer that runs at evaluation (`const X_SET = new Set(X_TYPES)`) keeps its dependency above it. Assembly-order inversions on record, all call-time and safe: `makeInitialState` calls `migrate`; `12_trunk` calls into `24_ephemeris/`; `08_export-layer` calls cartographia's renderer.

**Turnover.** After every cut, and at any session close that changed the record: edit the documents in place to match the tree, run the doc gate (DOCS GREEN) and `prove_teeth.py` (all eleven OK; it exits non-zero on a MISS), sweep every added line for em dashes and banned phrases, commit, push, and wait for CI on the head commit. After a rewrite that shrinks a document, rebaseline with `check_docs.py --docs docs --src cartulary-src --baseline docs/.turnover-baseline.json` once a Python sweep shows nothing newly authored: the gate counts against the baseline, so a stale higher count lets new dashes through. The em-dash probe writes into this file, whose baseline of 3 is the three entity forms named in the em-dash rule under Working with Drak; a rewrite that drops that line needs a rebaseline before the probe bites again. `--write-facts FILE` regenerates the derived section of `facts.json`; published figures, assertions, spans, and required strings are edited by hand when the documents change what they state. The six documents' roles and rules are in `tools/turnover/conventions.md`.

**Finals** (release prep only, never per cut). Extract each tarball in `deps/` into `inlining/node_modules/` (scoped packages under `@babel/` and `@fontsource/`; the exact loop is in the repository README), then `python3 inlining/build_inline.py finals`, then `node inlining/validate_html.js` on each output. `finals` inlines the libraries and both fonts, precompiles the JSX, and swaps the shell head's CDN tags (d3 7.8.5, babel 7.23.5, the dev form) for pinned d3 7.9.0 and babel-standalone 7.29.4. Do not "fix" the shell head: the zero-external-URL rule is about the built finals. Since 2026-10-24 `finals` writes its temporary JSX into a fresh directory from Python's `tempfile` rather than to `/tmp`, and reads and writes the build as UTF-8 bytes. Finals are never committed.

**Shipping.** The ship gate is Drak's pass on the finals themselves, never on the working file: the precompiled build is its own code path (JSX compiled ahead of time, libraries and fonts inlined), and the working file exercises none of it. Before his pass, run the headless probes against the precompiled final. **Tags.** Two forms. A revision's tag is `v<version>_r###`: a lower-case `v`, the line's version with its dot, then `_r` and the zero-padded counter, the same pair a working copy's file name carries (`v1.7_r001`). A release's tag is `v<version>_Release`, with a capital R (`v1.7_Release`). No spaces; git refuses them. A revision tag marks a passed state and goes on the commit CI went green on, which after a cut is its turnover commit; a bare freeze commit is doc-gate red until its turnover lands. The previous line's shipped tree is the new line's r000 and is never tagged (v1.7's r000 is the tree `v1.6.1_Release` marks), so a line's first tag is its r001. A patch continues its line instead of opening one: v1.6.1 bumps `VERSION` to `'1.6.1'` but keeps v1.6's count, so its first cut is r052, tagged `v1.6.1_r052`, the first tag in this form, and it ships with its own release tag, `v1.6.1_Release` (Drak, 2026-10-23). The release tag goes on the ship-turnover commit once CI is green there; the ship turnover changes only documents, so that commit builds the same finals as the line's last revision tag. A tag push re-runs CI on the tagged commit. The session's git credential refuses tag pushes, so Drak tags from his clone with the three lines `git pull` / `git tag v1.7_rNNN <sha>` / `git push origin v1.7_rNNN`, and the same three with `v1.7_Release` at the ship. The tags from before the rule (2026-10-23) keep their names: `r030` through `r051` on the v1.6 line's passed states, and `v1.6` on `8554fdf`, the v1.6 ship turnover. The anchor's name stays bare: `freeze` takes `r###` and names it `reference-r###-body.jsx`, which can't collide because only one exists at a time. Cut scripts carry the tag (Content cut).

**Opening and closing a line.** A line closes when the finals are live (the upload, not the build). At the close, the changelog freezes to `changelog-v<version>.md`, this handoff freezes to `handoff-v<version>.md`, and the version's plan and session blocks move from the roadmap to `roadmap-archive.md`, all verbatim; the live files start over with current state. A patch closes without a freeze: its record stays in the active changelog's between-lines section, its release text goes to `docs/release-notes/`, and the version line records the ship, as v1.6.1's did. A line opens with the `VERSION` bump, which puts the r-counter at r000: the previous line's tree as shipped, which takes no tag. A patch's bump (`1.6.1`) keeps the line's count instead (see Tags). The first product edit is r001, the line's first tag, and it flips the export's version literals. From the bump on, a bare r-number in the live documents means the new line's, so the opening turnover writes the version into the closed line's that remain in current-state text: this handoff and the roadmap's standing sections (`v1.6 r036`). **Commits.** One commit per gate-green step, with the revision in the message for cuts, written as its tag (`v1.7_r001: ...`, `Freeze v1.7_r001`, `Turnover v1.7_r001`); a freeze is a commit and a turnover is a commit. ## Architecture

**Glossopoeia, Ephemeris, and Cartographia are views with their own state slices, not sets of templates.** Each owns a `state.*` slice, registers through the node-source registry so it's graphable in Concordance, and has `migrate()` backfill its arrays; never model these as `BUILTIN_TEMPLATES` entries. Glossopoeia and Cartographia records are shaped `{ id, name, tags:[], fields:{} ... }` and render their fields through `EntryForm` with a per-type `*Schema()` function. **Ephemeris is the exception:** a celestial body is a flat record (`makeNewCelestialBody` in `24_ephemeris/`) with its own editor rather than `EntryForm`, and its `tags` is a comma-separated string, split on read. Code that assumes `tags` is an array breaks on bodies, the same family of mistake as the v1.3 tags crash.

- **`state.cartographia`** is a flat array of map records `{ id, name, tags:[], fields:{}, mapData:{ image, pins, drawing }, updatedAt }`, with the fixed field ids `cart-fld-description`, `cart-fld-scope-region`, `cart-fld-notes` rendered through `cartographiaMapSchema()`. `drawing` is `{ width, height, background, layers }`; a layer is vector (shapes) or raster (one bitmap, stored like a map image: a folder file `<map id>-<layer id>.<ext>` or a data URL). `ensureMapData` normalizes on every load and coerces rather than throws. Maps register as `SYNTH_TPL_MAP` (with outbound pin edges until v1.7's r042, since when Concordance draws the pins from the link index, which has read them since r041) and, since v1.7's r003, `refEligible:true`: a field can target maps on purpose (the template builder always offered Map), a reference to a map shows its name and opens it, and deleting a map clears the references to it after a confirmation counts them, since r042 the delete modal (`mapDeleteMessage`, `18_cartographia/04_index`, counted them from r003 until then). The JSON shapes are in the in-app help's JSON Save File Schema topic.
- **`state.mapStamps`**: stamps imported from stamp packs, world-scoped, ids namespaced by pack (`forest__pine`), every SVG body sanitized on import and again on load.
- **`state.glossopoeia`**: 21 record arrays plus `workspaceNotes` and `ui`, records `{ id, langId, name, tags:[], fields:{} }`. The schemas are in the frozen design docs `docs/glossopoeia-design-handover.md` and `docs/glossopoeia-phase-two.md`.
- **`canvasSlot`.** `EntryView` and `EntryForm` take an optional canvas node rendered above the fields; Cartographia fills it, since v1.7's r007 a corpus's page puts its reading order in `EntryView`'s, since r008 a story's page puts its tabs in both, since r009 the People tab puts its lists in `EntryView`'s, and since r011 the Outline tab its tree. Reuse it for any future canvas-over-form view. Since v1.7's r022 `EntryView` also takes `wide`: its column widens to the pane, and every child but one marked `entry-view-full` stays in the reading width, centered as before; the Timeline tab is the one that fills it.
- **Panels** (since v1.7's r008). `EntryView` and `EntryForm` draw a template's fields in panels when they're given `panels` (`[{ id, label }]`) and a field names its panel (`field.panel`): the fields in no panel first, then each panel under a heading that folds it (`fieldPanelSegments`, `FieldPanelHeading`), so a half-width pair never straddles a heading. The folds are the caller's (`foldedPanels`, `onTogglePanel`). Without panels both draw as before. In view an empty field doesn't show, so an open panel with nothing filled in says so.

## Carry-forward facts

- **Zero network requests is a rule** (Drak, 2026-10-23, v1.6 r051): a request anywhere in the application is a defect to cut, not a feature with a fallback. The SVG download embeds the map font from the page's own inline stylesheet; the development build, whose head loads fonts by link, falls back to the viewer's serif in the download, and that's expected.
- **Concordance opens with an empty template filter** (v1.5 r134, by design); **all** and **none** recover it. Don't "fix" it back to all-on.
- **Synthetic-node positions persist** across reload, with force containment keeping the graph compact (v1.5 r131-r132).
- **v1.6 r001 edge cases, accepted:** a map's `calendarId` is dropped; an unsaved map edit is lost on reload; an imported `.template.json` with `kind:"map"` is self-healed by `migrate()`.
- **Pre-v1.6 em dashes are frozen.** The rule governs newly authored text only. At the session-16 count the source carried 1,111 older ones, 283 of them in the in-app help, and none get swept.
- **The undo history covers the map editor only.** Everywhere else, Version History and the exported `.json` are the safety net.
- **The auto-save writes 250 ms after the last change** (`12_trunk`), and the write itself takes a moment more, so a probe's read of the saved world waits it out (r011's waits 600 ms; reading and reloading too soon cost its first full run 13 checks). Since v1.7's r039 a Save that closes an editor writes at once, and a pending save goes out when the page is hidden and on `pagehide` (Architecture, Saving), so a reload or a closed tab straight after an edit keeps it, as r039's probe found in Chromium.
- **Nine browser probes at once are too many for this sandbox.** At r012 two of nine crashed, one on a 30-second load timeout and one when its page died, and both ran clean alone; run the regression probes a few at a time, and rerun a crash alone before reading it as a result.
- **A picker's option is an entry's bare name unless its field lists more than one template**, when the template's name follows in parentheses (`formatEntryLabel`, inside `EntryRefEditor`); a field open to any template lists bare names. r012's K3 and r015's P1 each expected the other form on their first run.
- **Wait for probes by their processes.** Start them from one shell, each in the background, and `wait`. Two other waits have hung: at r012 a loop on `pgrep -fc 'node probe_'` also counted the shell running the loop, whose command line held the pattern, and at r013 a loop waiting for each run's total line never ended, because one mutant's run stopped before printing it, as a mutant's may.
- **A probe's default timeout reaches navigation too.** Playwright's `setDefaultTimeout` sets the wait for `goto` along with every click and selector, and the working build compiles its JSX in the page, so it can take longer to load than a click should wait. r016's mutant runs, with a five-second default, failed at their first `goto` until the probe set `setDefaultNavigationTimeout` apart from it.
- **The session's file-writing tool turns `\uXXXX` escapes into the characters.** r013's first assembly of its cut, written through it, put a literal ·, ×, the arrows, and non-breaking spaces into code that writes them as escapes. Assemble a cut's source with Python, or read its non-ASCII lines before running the cut.
- **The default calendar is Common Year** (v1.7 r001): the Gregorian months with no leap rule. Worlds saved before keep the name they stored, often Gregorian, by Drak's call; nothing renames a stored calendar.
- **What a browser answers when asked to keep Cartulary's storage** (Drak's pass of v1.7's r039, a page opened from a file): Chrome and Brave answer no without asking, so Settings' Browser storage row reads May be cleared, and Firefox asks with a prompt of its own, Allow or Block, with Remember this decision. A page opened from a file in a Chromium browser is the case r040's backups and the exported `.json` are for.
- **A probe can't set Chromium's storage quota on cue.** CDP's `Storage.overrideQuotaForOrigin`, set before the page first opens its storage, makes a write past it abort, and raised later it lets the next write land; lowered again in the same session it let a 3 MB write through a 1 MB quota, and an automatic snapshot written just after a save had hit the quota slipped under it (r039's experiments, not documented behavior). The override names an origin, so r039's probe served the build from an `https` origin of its own, set the quota before the page opened for the save's failure, and had a stub throw `QuotaExceededError` on the snapshots' keys for the snapshot notes.
